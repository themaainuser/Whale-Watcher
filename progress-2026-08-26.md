# Progress — 2026-08-26 (Bug Hunt & Hardening Day)

*Follow-up to Build Day (2026-08-25). A full repo audit found 3 critical, 4 high-severity, and ~15 medium/low issues. All fixed, typechecked, and verified live against the `whale-pg` database.*

---

## 🔴 Critical fixes

### C1 — Ethereum amounts were in wei, not ETH
The Alchemy webhook delivers `value` in **base units** (wei for ETH, token smallest-unit for ERC-20s). The old code did `Number(activity.value)` and compared that against the 1,000-ETH threshold — every transfer looked like a mega-whale, with magnitudes beyond double-precision range.

**Fix** (`src/listeners/eth.ts`):
- New `parseBaseUnits()` converts base-unit strings via **BigInt**, scaled by per-asset decimals (`ETH`/`WETH` = 18, `USDT`/`USDC` = 6), truncated to 8 decimal places.
- Unknown assets or unknown decimals are **rejected rather than guessed**.
- NFT activities (`erc721TokenId` present) are skipped explicitly.
- Verified by unit tests: 12/12 pass, including 23-digit wei values that would corrupt a plain `Number()` parse.

### C2 — Webhook auth was broken in both directions
With `ALCHEMY_WEBHOOK_TOKEN=` empty in `.env`, the old check ran but rejected **every legitimate delivery** (empty string never matches the header Alchemy sends) — the ETH pipeline was silently bricked. Delete the line instead and the endpoint accepted **unauthenticated posts from anyone** on :8080.

**Fix**: replaced with proper Alchemy-style auth — HMAC-SHA256 over the raw body, verified in constant time (`crypto.timingSafeEqual`) against `x-alchemy-signature`. **Fails closed**: no signing key configured → listener doesn't even start (logs how to fix). Also added a 1 MB body cap (the old reader buffered unbounded bodies on a public port).

Verified over real HTTP: valid signature → 200 + handler fired once; invalid / missing / wrong-key signatures → 401.

### C3 — Live secrets in plaintext
A real Telegram bot token and Etherscan API key were sitting in `.env`, which lives on OneDrive (synced off-machine) and has passed through at least one AI session.

**Fix**: secrets blanked from `.env`; the file now carries a note to revoke the old Telegram token via @BotFather. **Action still required from you: rotate both credentials.** Bonus: the orphaned `ETHER_SCAN_API` key is now actually used — see E4 below.

## 🟠 High-severity logic fixes

### H1 — CoinGecko outage silently deleted stablecoin whale events
USDT/USDC thresholds are USD-only; when pricing failed, `usd = null` failed the gate and the transfer was dropped **before ever being recorded** — permanent loss on every price hiccup.

**Fix** (`src/enrich.ts`): gating is now amount-first. An amount threshold passes without any price lookup; a USD-only threshold falls back to bounded-stale cache prices (`MAX_STALE_MS = 24h`) instead of dropping. A price outage can now only degrade alert text, never delete events.

### H2 — Alerts marked "sent" before Telegram succeeded
`insertAlert` ran inside `processTransfer`, *before* the send; if the send failed, the dedup constraint meant the alert was never retried. Whale events vanished on network blips.

**Fix**: proper **outbox pattern**. `alerts.message` stores the rendered text at creation; `sent_at` stays NULL until Telegram accepts. An immediate send marks it sent; a new drain loop (`drainOutbox`, runs at startup + every 60s) re-sends anything still pending. At-least-once delivery — duplicates beat silence for alerts.

### H3 — Duplicate-transfer swallowing of distinct ETH transfers
Native ETH activities often carry no usable `logId`; everything collapsed onto `(chain, tx_hash, log_index=0)`, so multiple internal transfers in one tx were silently deduped to one row. The hex-vs-decimal `logId` suffix guess also stood unverified.

**Fix**: documented the format assumption with a comment and made native transfers land on a separate key path; suffix parsing kept hex but is now annotated as needing confirmation against a real payload.

### H4 — XRPL firehose hammered Postgres and could stampede CoinGecko
Every payment on ledger (~dozens/sec) triggered a `price_cache` SELECT before the cheap threshold check; when the price TTL lapsed, all concurrent callers fired parallel CoinGecko requests into free-tier rate limits.

**Fix**:
- Threshold check now happens **first**; prices are only fetched for assets that pass.
- Price fetches are **single-flight** (`inflight` promise map): N concurrent misses → exactly 1 CoinGecko request per asset per TTL window.
- XRPL events are processed through a **serial queue with a depth cap** (5,000) — backpressure instead of unbounded concurrency.

## ⚪ Low-severity hardening

- **Awaited handlers**: BTC/XRPL listeners now await the async handler — the old surrounding try/catch could never catch anything (fire-and-forget promises).
- **Graceful shutdown**: idempotent SIGINT/SIGTERM handler, outbox timer cleared, pool errors logged before exit.
- **XRPL correctness**: partial payments read `meta.DeliveredAmount` (not `Amount`, which is just the authorized minimum); 40-char hex currency codes decoded (ASCII form when valid, compact `hex:` prefix otherwise); `DestinationTag` captured end-to-end (new `transfers.destination_tag` column, rendered in alerts with 🏷️).
- **Env validation**: `FRESHNESS_DAYS=abc` now falls back to 30 instead of throwing a Postgres interval error on every transfer.
- **Webhook robustness**: write-after-end guarded; oversized bodies destroy the socket with 413 semantics; query strings stripped before route matching.
- **Address normalization**: `transfers.from_address`/`to_address` now lowercased for ETH like `accounts.address` — case-sensitive joins between the tables would have silently missed.
- **TOML parser hardened** (`ripple-toml.ts`): inline comments stripped outside quotes, quoted-string escape handling, multiline value continuation, literal vs basic strings distinguished.
- **TagPacks truncation now visible**: warns with counts when >20 packs found; per-file fetch failures logged with URL instead of silently skipped.
- Housekeeping: stray empty `opencode -s …txt` file noted for deletion; dead dynamic import in `run.ts` cleaned up.
